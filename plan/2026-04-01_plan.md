## Detailed Plan

### 1. Smart Email Triage & Calendar Sync (GREEN) — Priority 1
**Impact:** Very High | **Effort:** 120 h (2.5 weeks) | **Confidence:** High

**Overview:**  
Automates Master’s inbox and calendar integration. Classifies emails, auto-acts on receipts/meetings/newsletters, parses boss’s HTML schedules into calendar events, drafts low-stakes replies. Directly solves a top pain point.

**Resource Requirements:**
- 🆓 Hosting: Runs as OpenClaw skill (no external hosting)
- 🆓 APIs: Microsoft Graph API, OpenRouter free tier
- 🧰 Skills: Build new `email-triage-sync` skill; reuse patterns from `ms-forms-auto`
- 💸 Costs: $0
- 🔑 Master must provide: Microsoft 365 credentials + Azure AD app (Mail.Read, Calendars.ReadWrite)

**Prerequisites:** Master completes OAuth consent and provides client ID/secret.

**Feasibility:** ✅ Autonomous build; requires one-time Master setup.

**Implementation Steps:**
1. **Setup (4 h):** Scaffold Node/TypeScript project; set up secure credential storage; create Azure AD app and document setup.
2. **Development (80 h):** Implement Graph API wrappers, email delta sync, classifier (fine-tune with Master’s labeled data), auto-actions (receipts→CSV, invites→accept, newsletters→daily digest, boss schedules→calendar events), reply drafter, task extractor, and simple dashboard.
3. **Testing (12 h):** Unit tests; dry-run on past 30 days; phased rollout (read-only → individual auto-actions).
4. **Deployment (4 h):** Install skill, add `~/.openclaw/skills/email-triage-sync` symlink, schedule cron (every 30 min work hours), document usage.
5. **Maintenance:** Weekly accuracy review, monitor Graph quotas.

**Blockers & Mitigations:**
- OAuth issues: follow Azure AD best practices, use admin consent if needed.
- Misclassification: implement “quarantine” folder and weekly manual review.
- Rate limits: use delta queries and batch requests.

**Success Criteria:**
- Inbox reduced >80%; boss schedules auto-added; receipts filed; daily newsletter digest; <1% false-positive meeting accepts.

**Impact:** Very High | **Effort:** 200 h (4 weeks) | **Confidence:** High

**Overview:**  
Aggregates real-time Web3 data (on-chain metrics, token launches, DeFi yields, NFT trends, news), filters noise with NLP, and delivers daily digest + instant Telegram alerts. Provides research edge for trading and NFT project.

**Resource Requirements:**
- 🆓 Hosting: Vercel or Cloudflare Workers (free tier) + free DB (Neon/Atlas)
- 🆓 APIs: Dune, DeFiLlama, Etherscan (free key), CoinGecko, Reddit, Discord; Twitter optional ($100/mo)
- 🧰 Skills: Standalone app; can be wrapped as skill for internal triggers
- 💸 Costs: $0 (skip Twitter); $100/mo if include Twitter
- 🔑 Master must provide: Etherscan API key, Discord bot token, Telegram bot token; Dune account (free)

**Prerequisites:** Bot tokens and API keys.

**Feasibility:** ✅ Autonomous with free resources; needs Master’s tokens.

**Implementation Steps:**
1. **Setup (4 h):** Repo + Next.js/serverless; free PostgreSQL; Vercel deploy.
2. **Development (140 h):** Connectors (Dune queries, DeFiLlama, Etherscan, CoinGecko, Reddit, Discord), NLP classifier (OpenRouter free model), alert rules engine, daily digest generator (Markdown), live Telegram alerts, interactive dashboard, knowledge base.
3. **Testing (12 h):** Mock sources, validate classification, test rules/digest, load test.
4. **Deployment (8 h):** Deploy, configure cron (5 min for on-chain, 15 min for social), set Telegram webhook/polling, document rule customization.
5. **Maintenance:** Weekly health checks, monitor limits, adjust classifier with feedback.

**Blockers & Mitigations:**

- Rate limits: cache, multiple keys, backoff.
- False positives: enable Master feedback to improve model.

**Success Criteria:**
- Daily digest each morning; <5 min alert latency; false positive <20%; Master reports saved research time.
