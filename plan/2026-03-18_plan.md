### 1. Japanese Learning Acceleration Engine (GREEN)
**Impact:** High | **Effort:** ~22 hours (14h + 50% buffer) | **Confidence:** High

**Overview:**
A contextual Japanese learning system that embeds vocabulary acquisition into Master's existing interests (crypto, tech, travel, gym). Delivers spaced repetition reviews via Telegram, curates Japanese content aligned with his domains, and auto-generates travel phrase packs when Japan trips approach. Goes beyond Duolingo's generic curriculum by making learning interest-driven.

**Resource Requirements:**
- 🆓 Free hosting: OpenClaw workspace (local Node.js scripts + cron)
- 🆓 Free APIs/models: OpenRouter free tier (for content generation), Telegram Bot API (already configured)
- 🧰 OpenClaw Skills needed: None new — uses existing cron + message tools
- 💸 Costs: $0
- 🔑 Master must provide: Nothing (Duolingo streak is optional scraping; system works without it)

**Prerequisites:** None

**Feasibility Assessment:**
- ✅ Can build autonomously with current resources
- ✅ All components are local scripts + Telegram delivery
- ✅ Free open-source SRS algorithms available (SM-2)

**Detailed Implementation Steps:**

1. **Setup Phase** (3 hours)
   - Create repo `ClaireAICodes/japanese-learning-engine`
   - Initialize Node.js project with dependencies: `node-telegram-bot-api`, `node-cron`, `marked`
   - Create vocabulary database schema (JSON-based): categories (crypto, tech, travel, gym, general), JLPT levels, spaced repetition metadata
   - Set up project structure: `src/vocabulary/`, `src/scheduler/`, `src/content/`, `src/telegram/`

2. **Development Phase** (8 hours)
   - **Module 1: Vocabulary Generator** — Build domain-specific vocabulary bank: crypto terms (暗号通貨, ブロックチェーン, NFT), tech (プログラミング, AI, クラウド), travel (電車, レストラン, 写真), gym (筋トレ, ベンチプレス, スクワット). Each entry: kanji, hiragana, romaji, English, example sentence, category
   - **Module 2: SM-2 Spaced Repetition Engine** — Implement SuperMemo-2 algorithm for optimal review scheduling. Track: ease factor, interval, repetition count, last review date per vocabulary item
   - **Module 3: Telegram Review Bot** — Commands: `/review` (get 5 cards), `/stats` (streak, accuracy), `/category [name]` (focus on domain). Auto-sends morning (8 AM) and evening (7 PM) review batches via cron
   - **Module 4: Content Curator** — Weekly Japanese content recommendations: crypto/tech YouTube channels (つみたてNISA解説, Hikaru), travel phrases, J-pop lyric breakdowns. Delivered via Telegram every Monday
   - **Module 5: Travel Prep Module** — Detect Japan trip keywords from calendar events; auto-generate phrase packs for restaurants, trains, convenience stores, photography shops, and gyms

3. **Testing Phase** (2 hours)
   - Run full vocabulary import and verify all entries parse correctly
   - Test SM-2 algorithm: simulate review cycles and verify interval progression
   - Test Telegram delivery: send sample review batches, verify formatting
   - Test cron scheduling: verify morning/evening triggers fire correctly

4. **Deployment Phase** (1 hour)
   - Install as OpenClaw cron job: morning review at 08:00 SGT, evening review at 19:00 SGT
   - Content curator cron: weekly Monday 09:00 SGT
   - Deploy vocabulary DB to workspace storage

5. **Maintenance Phase** (ongoing)
   - Weekly: add new vocabulary based on Master's weak areas
   - Monthly: review accuracy metrics and adjust difficulty
   - Monitor: Telegram delivery success rate

**Potential Blockers & Mitigations:**
- Duolingo scraping unreliable → System works independently; skip Duolingo integration initially
- Vocabulary might not match Master's actual level → Start with JLPT N5-N4 and adjust based on review accuracy
- Telegram message limits → Batch reviews into single messages with inline formatting

**Success Criteria:**
- Master receives 2 daily review batches (morning + evening) consistently
- Vocabulary database has 200+ entries across all domains
- Weekly content recommendations delivered every Monday
- Travel phrase packs auto-trigger when Japan trip detected in calendar

### 2. Trading Signal-to-Execution Pipeline Design (GREEN)
**Impact:** High | **Effort:** ~28 hours (18h + 50% buffer) | **Confidence:** High

**Overview:**
Architecture and working prototype for an automated trading pipeline: TradingView webhook → risk management → paper trading execution → portfolio dashboard via Telegram. This is the foundational layer connecting signal generation to actual order execution. Paper trading mode only — zero real capital at risk. Bridges the gap between "having trading ideas" and "automated bot with market edge" (Master's stated dream).

**Resource Requirements:**
- 🆓 Free hosting: Vercel (webhook endpoint) + OpenClaw workspace (bot engine)
- 🆓 Free APIs/models: Binance testnet API (free), Bybit demo trading API (free), TradingView webhook alerts (free with account)
- 🧰 OpenClaw Skills needed: None new — uses existing cron + message tools
- 💸 Costs: $0 (paper trading only, testnet APIs are free)
- 🔑 Master must provide: TradingView account (for webhook alerts setup — one-time 5 min)

**Prerequisites:** None (paper trading requires no exchange API keys)

**Feasibility Assessment:**
- ✅ Can build autonomously with current resources
- ✅ Binance/Bybit testnet APIs are free and well-documented
- ⚠️ Minor Master input needed: TradingView webhook URL setup (5 min)

**Detailed Implementation Steps:**

1. **Setup Phase** (4 hours)
   - Create repo `ClaireAICodes/trading-pipeline`
   - Initialize Node.js project: `express` (webhook server), `axios` (exchange APIs), `ws` (WebSocket), `node-cron`
   - Design architecture document with data flow diagrams
   - Set up project structure: `src/webhook/`, `src/risk/`, `src/exchange/`, `src/portfolio/`, `src/dashboard/`

2. **Development Phase** (10 hours)
   - **Module 1: Webhook Receiver** — Express HTTP endpoint accepting TradingView alert payloads (JSON). Parse signal: symbol, action (buy/sell), price, timeframe. Queue signals for processing with timestamp and idempotency check
   - **Module 2: Risk Management Engine** — Configurable rules: position sizing (fixed % of portfolio, default 2%), stop-loss (default 2% below entry), take-profit (default 3% above entry), max daily drawdown limit (5%), cooldown between trades (15 min). All configurable via JSON config file
   - **Module 3: Exchange Abstraction Layer** — Unified interface for paper trading: Binance testnet REST API, Bybit demo API. Methods: `placeOrder()`, `cancelOrder()`, `getBalance()`, `getPositions()`. Paper mode: local JSON simulation with realistic slippage (0.05%)
   - **Module 4: Portfolio Tracker** — Real-time state: open positions, P&L, trade history, win rate, average R:R ratio, max drawdown, Sharpe ratio approximation. Persisted to workspace JSON file
   - **Module 5: Telegram Dashboard** — Commands: `/positions` (open trades), `/pnl` (daily/weekly P&L), `/history` (last 10 trades), `/config` (view risk settings), `/kill` (emergency stop all), `/resume` (re-enable trading). Daily summary at 23:00 SGT

3. **Testing Phase** (2 hours)
   - Unit test webhook parsing with sample TradingView payloads
   - Test risk engine: verify position sizing, stop-loss triggers, daily drawdown halt
   - Paper trading simulation: run 50 historical signals through full pipeline
   - Verify Telegram dashboard commands return correct data

4. **Deployment Phase** (2 hours)
   - Deploy webhook endpoint to Vercel (free tier, auto-scaling)
   - Install Telegram bot commands as OpenClaw cron
   - Daily P&L summary cron at 23:00 SGT
   - Health check cron: alert if webhook endpoint is down

5. **Maintenance Phase** (ongoing)
   - Monitor webhook uptime via health check
   - Weekly: review paper trading performance, adjust risk parameters
   - Track: signal accuracy, execution latency, slippage vs. expected
   - When ready for live: requires Master's explicit approval + real API keys

**Potential Blockers & Mitigations:**
- TradingView webhook requires paid plan → Use free alternative: polling TradingView public API or manual signal input via Telegram command
- Exchange API rate limits → Implement request queuing and retry logic
- Paper trading slippage unrealistic → Add configurable slippage model (0.05-0.2%)
- Signal parsing format changes → Flexible parser with regex fallback

**Success Criteria:**
- Webhook endpoint live and receiving test signals
- Paper trades executing with proper risk management
- Telegram dashboard showing real-time portfolio state
- 50+ paper trades logged with win rate and R:R data
- Architecture doc serves as blueprint for future live trading upgrade
