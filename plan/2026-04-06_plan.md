## 1. Japanese SRS Vocabulary Trainer for OpenClaw (GREEN)

**Impact:** High | **Effort:** ~8 hours | **Confidence:** High

**Priority Score:** 8/10 (High Impact × High Feasibility / Moderate Effort)

**Overview:**
A lightweight spaced-repetition vocabulary system delivered via Telegram. Master receives 2–3 flashcards each morning, auto-selected from JLPT word lists and tracked by a SM-2-inspired algorithm stored in a simple JSON file. Directly accelerates Japanese retention beyond Duolingo's pace — aligned with Master's noted learning goals.

**Resource Requirements:**
- 🆓 Free hosting: None needed — runs as local script via OpenClaw cron
- 🆓 Free APIs: No external APIs needed for core (seed data is static JSON); optional JLPT API for future expansion
- 🧰 OpenClaw Skills: None needed; delivered via cron job + `message` tool
- 💸 Costs: **$0**
- 🔑 Master must provide: Nothing

**Prerequisites:** None

**Feasibility Assessment:**
- ✅ Fully buildable autonomously with current resources

**Detailed Implementation Steps:**

1. **Setup Phase** (1.5 hours)
   - Create `data/japanese-srs.json` schema: `{words: [{id, kanji, kana, romaji, meaning, example, ease: 2.5, interval: 0, repetitions: 0, nextReview: date}], streak: 0, lastSession: date}`
   - Seed vocabulary JSON with 200+ JLPT N5 words (kanji, kana, romaji, English, example sentence) — expand to N4/N3 later
   - Create `scripts/srs-japanese.js` with SM-2 core logic (ease factor adjustment, interval calculation, next-review scheduling)

2. **Development Phase** (4 hours)
   - Implement word selection: fetch words where `nextReview ≤ today`, pick 3 prioritized by lowest ease/shortest interval
   - Build flashcard formatting: Telegram-friendly with tap-to-reveal (use interactive buttons for answer options: correct/wrong/hard)
   - Implement response handler: on tap, update SM-2 state (ease ±0.2–0.6, interval × multiplier), recalculate nextReview
   - Add streak tracking and weekly progress stats (words mastered, weak areas, accuracy rate)

3. **Testing Phase** (1.5 hours)
   - Dry-run word selection against seeded data
   - Verify SM-2 math: correct answer → interval grows; wrong → resets
   - Manual test: send sample flashcards, simulate responses, verify state updates in JSON

4. **Deployment Phase** (1 hour)
   - Create cron job: daily at **8:00 AM SGT** → trigger SRS session via Telegram with interactive buttons
   - Register response handler in OpenClaw config for button callbacks
   - Add optional Sunday progress report cron (weekly stats summary)

5. **Maintenance Phase** (ongoing)
   - Monthly: expand vocabulary pool (N4, N3 words) — automated via script fetching curated lists
   - Monitor: JSON file size, ensure no state corruption
   - Update: if Master struggles with specific word categories, prioritize those

**Potential Blockers & Mitigations:**
- Telegram button callbacks require interactive message support — if not available, fall back to text-based responses (type "correct"/"wrong")
- JSON state corruption — add simple validation on load; backup to `data/japanese-srs.json.bak`
- Word pool exhaustion — seed generously (200+ N5), expand to N4/N3 progressively

**Success Criteria:**
- Master receives 3 flashcards daily at 8 AM SGT
- Responses update SRS state within seconds
- Weekly progress report shows streak, accuracy, and mastered count
- Master confirms usefulness within first week

## 2. Web3 & Crypto Weekly Alpha Research Digest (GREEN)

**Impact:** High | **Effort:** ~12 hours | **Confidence:** High

**Priority Score:** 6.5/10 (High Impact × High Feasibility / Higher Effort)

**Overview:**
A weekly curated digest scanning the crypto/Web3 ecosystem and delivering a concise, opinionated briefing every Sunday morning at 8 AM SGT. Covers narrative shifts, notable launches, market signals, and actionable takeaways — tailored to Master's NFT project and trading interests. Replaces hours of manual research with a single, high-signal read.

**Resource Requirements:**
- 🆓 Free hosting: None — runs as local script via cron
- 🆓 Free APIs: CoinGecko (free tier), CryptoPanic RSS, DefiLlama API, Dune public dashboards, GitHub trending API
- 🧰 OpenClaw Skills: None needed; delivered via cron + `message` tool
- 💸 Costs: **$0** (all free API tiers sufficient)
- 🔑 Master must provide: Nothing

**Prerequisites:** None

**Feasibility Assessment:**
- ✅ Fully buildable autonomously with current resources

**Detailed Implementation Steps:**

1. **Setup Phase** (2 hours)
   - Research and catalog free data sources with rate limits, response formats, and coverage:
     - CoinGecko: trending coins, market data, categories
     - CryptoPanic: aggregated crypto news with sentiment scoring
     - DefiLlama: TVL trends, protocol launches, chain metrics
     - GitHub trending: Web3 repos
     - Dune Analytics: public dashboard URLs for on-chain metrics
   - Create `scripts/alpha-digest.js` skeleton with modular source fetchers
   - Set up rate-limit-aware fetching (serialize requests, respect Retry-After)

2. **Development Phase** (6 hours)
   - Build each source module:
     - **Narratives module:** CoinGecko trending + CryptoPanic top stories (last 7 days)
     - **Launches module:** DefiLlama new protocols + major testnet/mainnet announcements
     - **Market signals module:** Top gainers/losers, unusual volume, whale alerts (CoinGecko + free whale tracking APIs)
     - **Tools module:** GitHub trending Web3 repos, new dev tools
   - Implement scoring/relevance filter: weight items matching Master's interests (NFTs, DeFi, L2s, Solana, trading tools) higher
   - Build digest formatter: Telegram-friendly sections with links, data timestamps, and "What This Means for You" actionable takeaways
   - Add deduplication: same story across multiple sources → one unified entry

3. **Testing Phase** (2 hours)
   - Run against live data, verify all API calls succeed
   - Check digest quality: is it actionable? Too long? Too short? Too noisy?
   - Manual review of first generated digest; refine scoring weights based on signal-to-noise

4. **Deployment Phase** (2 hours)
   - Create cron job: **Sunday 8:00 AM SGT** → generate and send digest via Telegram
   - Add alerting: if any source fails, log warning and still send digest with available data
   - Store last digest in `data/alpha-digests/` for history and pattern analysis

5. **Maintenance Phase** (ongoing)
   - Monthly: review source reliability, replace any deprecated APIs
   - Quarterly: expand to new categories (e.g., airdrop opportunities, NFT floor tracking)
   - Monitor: API rate limits, ensure no source silently breaks

**Potential Blockers & Mitigations:**
- API rate limits (CryptoPanic free tier: ~200 req/day) — serialize requests, cache intermediate results
- Data quality/noise — iterate on scoring weights; Master can provide feedback after first 2–3 digests to calibrate
- Source deprecation — modular design makes swapping sources straightforward

**Success Criteria:**
- Digest delivered consistently every Sunday at 8 AM SGT
- Contains 5–10 high-signal items with actionable takeaways
- Master confirms digest is useful and worth keeping (after 3 deliveries)
- Takes <2 minutes to read, sparks at least 1 actionable idea/week
