### 1. Email Triage & Smart Reply Automation (GREEN)
**Impact:** High | **Effort:** 6–9 hours | **Confidence:** High

**Overview:**
Build an OpenClaw skill that auto-classifies Master's M365 inbox (Urgent/Important/Newsletter/Notification), auto-archives noise, drafts reply templates for common patterns, and delivers a daily digest. Solves his #1 stated pain point: inbox overload.

**Resource Requirements:**
- 🆓 Free hosting: Runs inside OpenClaw (no separate host needed)
- 🆓 Free APIs/models: Microsoft Graph API (included with M365), OpenRouter free model for classification
- 🧰 OpenClaw Skills needed: **New skill** — `email-triage/`
- 💸 Costs: $0
- 🔑 Master must provide: One-time OAuth consent for Microsoft Graph API (App Registration in Azure AD)

**Prerequisites:** Azure AD app registration (30 min setup, Master approves permissions)

**Feasibility Assessment:**
- ✅ Can build autonomously with current resources
- ⚠️ Minor Master input needed: Azure AD admin consent for Mail.ReadWrite permissions

**Detailed Implementation Steps:**

1. **Setup Phase** (2 hours)
   - Register app in Azure AD → app-phil-email-triage (mail:readwrite)
   - Store credentials in workspace config (gitignored), implement OAuth2 token flow
   - Create skill skeleton under `skills/email-triage/SKILL.md`

2. **Development Phase** (3–4 hours)
   - Email fetcher using Graph API delta queries (only new messages)
   - Classification engine via OpenRouter prompt: categorize into 4 buckets with confidence scores
   - Rule engine: auto-archive newsletters/notifications, flag urgent/important
   - Draft reply generator for common patterns (meeting confirmations, scheduling)
   - Daily digest formatter (markdown summary)

3. **Testing Phase** (1–2 hours)
   - Dry-run mode for 3–5 days: classify only, take no actions
   - Compare classifications against Master's manual triage
   - Refine prompts based on false positives

4. **Deployment Phase** (1 hour)
   - Install skill via symlink to `~/.openclaw/skills/`
   - Set up cron: scan every 30 min, digest at 9 AM SGT daily
   - Exit dry-run mode after Master approval

5. **Maintenance Phase** (ongoing)
   - Monitor classification accuracy weekly
   - Refresh Graph API tokens automatically (refresh token flow)
   - Adjust rules as Master's email patterns change

**Potential Blockers & Mitigations:**
- OAuth complexity → Use incremental consent, start with Mail.Read only
- False classifications → Dry-run period with feedback loop
- Rate limits on Graph API → Batch requests, use delta queries

**Success Criteria:**
- >90% classification accuracy after tuning
- Master's inbox unread count reduced by 80%+
- Daily digest delivered reliably at 9 AM SGT

### 3. TradingView Watchlist Alpha Detector (GREEN)
**Impact:** High | **Effort:** 9–12 hours | **Confidence:** High

**Overview:**
An OpenClaw skill that monitors watchlist symbols for technical patterns (breakouts, RSI divergences, volume spikes, MA crossovers) and sends concise alerts. **Key workaround:** TradingView has no public API. Instead, use free price data APIs (Yahoo Finance via `yahoo-finance2`) with a configurable watchlist file, run pattern detection algorithms in OpenClaw, and link to TradingView charts in alerts.

**Resource Requirements:**
- 🆓 Free hosting: Runs inside OpenClaw
- 🆓 Free APIs/models: Yahoo Finance (free, no auth), OpenRouter free models for analysis summarization
- 🧰 OpenClaw Skills needed: **New skill** — `tv-watchlist-alpha/`
- 💸 Costs: $0
- 🔑 Master must provide: Symbol watchlist (text file)

**Prerequisites:** None

**Feasibility Assessment:**
- ✅ Can build autonomously with current resources
- ⚠️ Minor Master input needed: Confirm symbols to watch

**Detailed Implementation Steps:**

1. **Setup Phase** (2 hours)
   - Create `skills/tv-watchlist-alpha/` skeleton
   - Install `yahoo-finance2` npm package
   - Create `config/watchlist.json` template (symbol list + pattern config)

2. **Development Phase** (4–5 hours)
   - Data fetcher: Pull OHLCV + indicator data via Yahoo Finance (1h)
   - Pattern detection engine (2.5h):
     - RSI divergence (overbought/oversold with price divergence)
     - Moving average crossovers (SMA50/SMA200 golden/death cross)
     - Volume anomaly detection (2σ from 20-day average)
     - Support/resistance breach via pivot point analysis
   - Alert formatter: pattern name, confidence, key levels, TradingView chart link (1h)
   - Quiet hours + sensitivity config (0.5h)

3. **Testing Phase** (1–2 hours)
   - Backtest against 10 known symbols with historical patterns
   - Validate false positive rate (target: <20%)
   - Dry-run alerts for 1 week, compare against manual observation

4. **Deployment Phase** (1 hour)
   - Install skill, configure cron: scan every 30 min during market hours
   - Set up alert delivery via OpenClaw message

5. **Maintenance Phase** (ongoing)
   - Tune sensitivity thresholds based on alert quality
   - Add new patterns as needed
   - Monitor Yahoo Finance rate limits (generous for reasonable polling)

**Potential Blockers & Mitigations:**
- Yahoo Finance rate limits → Cache responses, 30-min polling is well within limits
- Data quality gaps → Fallback to multiple data sources if needed (e.g., CoinGecko for crypto)
- Not real TradingView data → Pattern detection is data-agnostic; results link to TradingView charts directly

**Success Criteria:**
- Alerts delivered during market hours with <5 min data freshness
- At least 1 actionable pattern detected per week
- Master finds alerts useful (qualitative feedback after 2 weeks)
