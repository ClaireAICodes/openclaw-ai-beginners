**Feasibility Assessment:** ✅ Can build autonomously with current resources.

**Detailed Implementation Steps:**

1. **Setup Phase** (2h)
   - Create `sentinel/` Node.js project; add dependencies (node-cron, sqlite3, @openclaw/sdk).
   - Define config: health thresholds, alert recipients, expected cron jobs list.
   - Initialize SQLite schema for metrics history.

2. **Development Phase** (10h)
   - Implement health checks:
     * `cron_check`: read crontab, compare to expected list.
     * `skill_logs`: scan gateway logs for recent failures.
     * `auth_check`: verify credential validity via gateway API.
     * `disk_space`: check filesystem free space.
   - Build hourly polling engine (node-cron).
   - Alert logic: classify critical/warning; send Telegram messages with context.
   - Auto-recovery actions:
     * Re-run cron installer if missing.
     * Send re-auth prompt to Master if credentials expired.
     * Alert low disk and optionally clean old logs.
   - Add sentinel self-logging and error handling.

3. **Testing Phase** (2h)
   - Simulate failures (remove cron entry, fill disk, mock auth expiry).
   - Verify correct alerts and safe recovery actions.

4. **Deployment Phase** (2h)

   - Load initial expected cron configuration.
   - Send activation confirmation to Master.
   - Document disable procedure.

5. **Maintenance Phase** (ongoing)
   - Monthly review logs; adjust thresholds.
   - Update if OpenClaw APIs change.
   - ~1h/month.

**Potential Blockers & Mitigations:**
- Gateway API changes: use stable endpoints; fallback to direct log parsing if needed.
- Telegram rate limits: batch alerts, use cooldown.
- False positives: tune thresholds, require condition persistence over 2 cycles.

**Success Criteria:**
