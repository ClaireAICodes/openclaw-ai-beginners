### 1. Intelligent Email Triage & Auto-Responder System (GREEN)

**Impact:** High | **Effort:** 3 days (24–32 hours) | **Confidence:** High

**Overview:**  
A modular system that automatically classifies Master's inbox, prioritizes emails by urgency/sender, and generates draft responses for routine messages. Includes CLI for quick commands (e.g., "archive all newsletters").

**Resource Requirements:**
- 🆓 Hosting: None (runs as OpenClaw cron job or local script)
- 🆓 APIs: IMAP, OpenRouter free LLM (step‑3.5‑flash)
- 🧰 Skills: Use existing `gog` for Gmail or custom IMAP integration
- 💸 Costs: $0
- 🔑 Master must provide: IMAP credentials (likely already available)

**Prerequisites:** None

**Feasibility Assessment:** ✅ Can build autonomously; only needs email access.

**Implementation Steps:**

1. **Setup (4h)**
   - Create `email-triage` repo with GitHub metadata.
   - Initialize Node.js project; install `imap`, `nodemailer`, `openai` (OpenRouter).

2. **Development (16h)**
   - Implement IMAP connection and unseen‑email fetch.
   - Build rule engine: domain/keyword regex, sender importance list.
   - Add prioritization scoring (importance × urgency).
   - Create template response system; integrate LLM for draft generation.
   - Build CLI: review mode, archive commands, learning from corrections.

3. **Testing (4h)**
   - Test with sample mailbox; avoid deletions (use labels first).
   - Tune classification rules; measure accuracy (goal >90% correct folder).
   - Validate response drafts for tone and correctness.

4. **Deployment (4h)**
   - Package as OpenClaw skill or standalone script.
   - Add cron (every 30 min); configure logging to memory/email‑triage.log.
   - Include dry‑run mode with summary report to Master.

5. **Maintenance (ongoing)**
   - Weekly review of misclassifications; adjust rules.
   - Monitor LLM usage; add fallback if rate‑limited.
   - Expand template library based on Master's feedback.

**Potential Blockers & Mitigations:**
- *IMAP connectivity issues* → use OAuth2 fallback; exponential backoff.
- *LLM rate limits* → cache common responses; set daily quota.
- *False positives* → require confidence threshold >70% for auto‑actions; allow easy undo via CLI.

**Success Criteria:**
- Inbox clutter reduced by ≥50%.
- Important emails never missed (100% detection of flagged senders).
- Master only reviews draft responses before sending.

### 8. Smart Photography Gallery Manager with Auto‑Curation (GREEN)

**Impact:** Medium | **Effort:** 8 days (64–80h) | **Confidence:** High

**Overview:**  
Automatically organize photo library by date/event/location, rate image quality (sharpness, exposure), detect duplicates, generate smart albums, and suggest best shots for social/portfolio. Include batch editing and web gallery.

**Resource Requirements:**
- 🆓 Hosting: Local processing on Master's machine (no hosting) or optional Vercel for UI (processing elsewhere)
- 🆓 APIs: None if local; cloud vision APIs would cost → avoid.
- 🧰 Skills: Build custom with OpenCV/sharp; no existing skill likely
- 💸 Costs: $0 (local); $5/mo if using small VPS for scheduled scans (optional)
- 🔑 Master involvement: none

**Prerequisites:** Access to photo directories.

**Feasibility Assessment:** ✅ Can build autonomously; may require local compute resources.

**Implementation Steps:**

1. **Setup (8h)**
   - Create `photo-manager` repo; define database schema (photos, albums, scores, duplicates).
   - Choose libraries: `sharp` (Node.js) or `Pillow` (Python); `opencv` for CV; `imagehash` for duplicates.

2. **Development (40h)**
   - Build scanner: recursively read directories; extract EXIF (date, GPS, camera settings).
   - Implement quality metrics: blur detection (Laplacian variance), exposure histogram analysis, noise estimation.
   - Duplicate detection: perceptual hashing; clustering similar images.
   - Album generator: group by date clusters (events) and GPS locations.
   - Basic subject detection: use lightweight pre‑trained model (e.g., COCO SSD via TensorFlow.js) or skip due to size.
   - Create "best of" selector: pick top‑N per album by composite score.
   - Add batch editor: crop, filter, exposure adjustments; export optimized for social media (auto‑crop to aspect ratios).

3. **Testing (8h)**
   - Test on a subset of 1000 photos; validate duplicate detection; check quality scores correlate with human judgement.
   - Ensure GPS data correctly clusters vacation shots.

4. **Deployment (8h)**
   - Build CLI: scan, generate albums, export web gallery (static HTML).
   - Optional: deploy static gallery to GitHub Pages.
   - Schedule weekly scan via cron.

5. **Maintenance (ongoing)**
   - Add support for new camera RAW formats.
   - Improve quality algorithm based on feedback.
   - Allow manual overrides (mark as favorite, hide).

**Potential Blockers & Mitigations:**
- *Large library processing time* → incremental scanning; process only new files; allow pause/resume.
- *CV model heavy* → use only lightweight metrics initially; add heavy analysis as optional.
- *Memory usage* → stream processing; limit concurrency.

**Success Criteria:**
- Entire library organized into dated/location albums.
- Duplicates reliably flagged.
- Master can quickly find and export best shots for social media.
