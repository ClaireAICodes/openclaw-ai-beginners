### 1. OpenClaw Health Monitor & Auto-Recovery System (GREEN)
**Impact:** High | **Effort:** 30 hours (3.75 days) | **Confidence:** High
**Priority Score:** 9/10

**Overview:**
Proactive monitoring of OpenClaw’s core operations (cron jobs, backups, agents) with auto-recovery. Addresses silent failures like the recent backup SIGTERM, ensuring reliable autonomous operation and reducing manual oversight.

**Resource Requirements:**
- 🆓 Free hosting: Runs on same OpenClaw host
- 🆓 Free APIs: Telegram Bot API (alerts)
- 🧰 OpenClaw Skills: `cron`, `message`, `session_status`, `agents_list`
- 💸 Costs: $0
- 🔑 Master must provide: None

**Prerequisites:** OpenClaw operational; Telegram bot configured.

**Feasibility Assessment:**
- ✅ Fully autonomous build with current resources

**Implementation Steps:**

1. **Setup Phase** (4h)
   - Create GH repo `openclaw-health-monitor` with proper metadata, add `AzureKn1ght` collaborator.
   - Init Node.js project; install `axios`, `node-cron`, `telegram-bot-api`, `fs-extra`.

2. **Development Phase** (18h)
   - Build health checks:
     * Cron status (parse logs or query scheduler)
     * Backup status (verify recent success)
     * Agent status (`agents_list`)
     * System metrics (disk, memory)
   - Persist state to JSON file.
   - Auto-recovery:
     * Retry failed backups with backoff
     * Restart stalled agents via gateway
     * Escalate failures to Telegram
   - Create minimal Express dashboard (`/health`).

3. **Testing Phase** (4h)
   - Unit tests + simulated failures (stop cron, fill disk, kill agent).
   - Dry run in sandbox.

4. **Deployment Phase** (4h)
   - Schedule via cron (every 30 min).
   - Configure Telegram alerts; verify dashboard.

5. **Maintenance (ongoing)**
   - Log rotation; threshold review.

**Blockers & Mitigations:**
- Cron introspection: parse logs as fallback.
- Alert spam: severity levels + debounce.

**Success Criteria:**
- First detection/recovery within 48h.
- Alerts received for simulated failures.
- Dashboard shows continuous uptime.

### 2. Email Triage & Calendar Sync Automation (GREEN)
**Impact:** High | **Effort:** 40 hours (5 days) | **Confidence:** High
**Priority Score:** 8/10

**Overview:**
Automates email processing and calendar creation. Connects via Gmail API to classify inbox, extract class schedules from boss’s HTML emails, create events, and auto-archive. Solves explicit pain point and saves daily time.

**Resource Requirements:**
- 🆓 Free hosting: OpenClaw host
- 🆓 Free APIs: Gmail API, Google Calendar API
- 🧰 Skills: `gog` (Google Workspace CLI), `cron`, `message`
- 💸 Costs: $0
- 🔑 Master must provide: Google OAuth2 credentials (client ID, client secret, refresh token) and consent to access email/calendar.

**Prerequisites:** `gog` skill installed and authenticated.

**Feasibility Assessment:**
- ⚠️ Requires Master’s one-time Google API credentials
- ✅ After setup, fully autonomous

**Implementation Steps:**

1. **Setup Phase** (6h)
   - Create GH repo `openclaw-email-triage`.
   - Init Node.js; install `gog`, `cheerio`, `node-cron`.
   - Document `gog` setup; request credentials from Master.

2. **Development Phase** (24h)
   - Email fetch: new messages via `gog` Gmail; classify by sender/subject.
   - HTML parser for class schedules (cheerio + regex) to extract date, time, location, topic.
   - Calendar integration: create events via `gog` Calendar; de-duplicate.
   - Auto-archive: label processed emails.
   - Manual override: email-based junk training.

3. **Testing Phase** (6h)
   - Use sample emails; verify extraction and event creation.
   - Test error handling and alerts.

4. **Deployment Phase** (4h)
   - Cron: fetch every 15 min during work hours.
   - Daily digest via Telegram each evening.
   - Logging + failure alerts.

5. **Maintenance (ongoing)**
   - Adjust rules as email formats change; quarterly credential checks.

**Blockers & Mitigations:**
- Gmail quotas: batch requests; stay well under 1M/day.
- HTML changes: fuzzy matching; flag uncertain emails for manual review.
- Token security: store encrypted or via OpenClaw secrets.

**Success Criteria:**
- Zero manual sorting for 2 weeks.
- 100% correct class events.
- Daily digest delivered reliably.

### 3. Automated Trading Signal Researcher (GREEN)
**Impact:** High | **Effort:** 55 hours (6.9 days) | **Confidence:** High
**Priority Score:** 7/10

**Overview:**
Continuous research scanning crypto markets for statistical arbitrage, funding anomalies, and cross-exchange divergences. Generates daily Telegram briefs with actionable insights, laying the foundation for a future automated trading bot.

**Resource Requirements:**
- 🆓 Free hosting: OpenClaw host
- 🆓 Free APIs: Binance/Bybit public endpoints; CCXT; CoinGecko free tier
- 🧰 Skills: `cron`, `message`, `web_fetch`, optional `gemini` (free models)
- 💸 Costs: $0
- 🔑 Master must provide: None for public data; optional exchange API keys for advanced features later.

**Feasibility Assessment:**
- ✅ Fully autonomous

**Implementation Steps:**

1. **Setup Phase** (8h)
   - Create GH repo `openclaw-trading-research`.
   - Init Node.js; install `ccxt`, `ta-lib`, `moment`, `jimp`.
   - Configure exchanges (Binance, Bybit, OKX).
   - Design data schema & storage.

2. **Development Phase** (32h)
   - Data pipeline:
     * Historical OHLCV for top 50 pairs.
     * Real-time order book & funding rates (polling/WebSocket).
   - Analysis modules:
     * Pairs trading (cointegration, z-score).
     * Mean reversion (Bollinger, RSI).
     * Momentum (MACD, volume).
     * Funding arbitrage.
   - Signal scoring: confidence, risk-adjusted return, backtest calibration.
   - Digest generator: markdown with tables/charts; top 5 signals.
   - Tracking: log signals for forward evaluation.

3. **Testing Phase** (8h)
   - Unit tests for indicators.
   - Backtest across 6 months; dry-run digest.
   - Load test for data fetch.

4. **Deployment Phase** (7h)
   - Cron: data every 6h; digest daily 8 AM.
   - Telegram delivery; failure alerts.
   - Documentation.

5. **Maintenance (ongoing)**
   - Weekly threshold review; monthly data pruning; expand modules.

**Blockers & Mitigations:**
- Rate limits: CCXT built-in throttling; cache data.
- Storage: prune OHLC to 90 days.
- Library changes: freeze versions in package.json.

**Success Criteria:**
- Daily Telegram digest by 8 AM with ≥3 signals.
- After 1 month, ≥20% show profitable setups in paper trading.
- Zero missed cron runs/unhandled exceptions.
