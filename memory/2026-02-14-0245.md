assistant: ## What This Script Does (Simple Explanation)

This is a **memory sync tool** that automatically copies your OpenClaw knowledge (MEMORY.md + daily notes) to a Notion database, turning your plain text notes into a beautiful, searchable knowledge base.

---

### The Big Picture

**OpenClaw** stores memories as Markdown files in two places:
1. `MEMORY.md` - your long-term curated memories2. `memory/YYYY-MM-DD.md` - daily logs (last 7 days by default)

**Notion** is a visual database where you want those memories to appear as nicely formatted pages with tags, categories, and proper formatting.

This script is the **bridge** between them. Every time it runs, it:
- Reads your memory files
- Figures out what's new or changed
- Creates/updates pages in Notion
- Remembers what it already synced (so it doesn't duplicate)

---

### Main Components (5 Pieces)

1. **NotionClient** - talks to Notion's API using `curl`
   - Creates pages, updates properties, lists all pages, archives old ones
   - Uses your Notion API key

2. **MemoryParser** - reads and extracts entries from your files
   - Looks for entries that start with `### ` under relevant sections
   - Gets title, body, source file, and date
   - Removes duplicates by hashing the content

3. **EntryClassifier** - automatically tags and categorizes each entry
   - **Content Type**: Research, Lesson, Decision, Pattern, Tutorial, Reference, Insight
   - **Domain**: AI Models, OpenClaw, Cost Optimization, Trading, Web3, Learning, Process, etc.
   - **Certainty**: Verified, Likely, Speculative, Opinion
   - **Impact**: High, Medium, Low, Negligible
   - **Confidence Score**: 1-10 rating
   - **Tags**: Keywords like `AI`, `FreeTier`, `Benchmark`, `Automation`, `Coding`, etc.

4. **MarkdownToNotion** - converts your markdown text into Notion's block format
   - Headers (`#`, `##`, `###`) → Notion headings
   - Lists (`-`, `*`, `1.`) → bulleted/numbered list items
   - Code blocks (```) → code blocks with language
   - Quotes (`>`) → quote blocks
   - Dividers (`---`) → horizontal dividers
   - Tables → code blocks (Notion tables need special handling)
   - Everything else → paragraphs

5. **SyncOrchestrator** - the conductor that runs everything
   - Loads sync state from `memory/notion-sync-state.json` (tracks which entries are already synced)
   - Processes entries one by one
   - Logs every action to `memory/sync-log.md`
   - Handles "orphan cleanup" - archives Notion pages that no longer exist in your local files

---

### How It Works (Step-by-Step)

1. **Start up** → Load config, API key, and previous sync state
2. **Parse files** → Read MEMORY.md + last 7 days of daily notes, extract entries
3. **Deduplicate** → Remove exact duplicates (same title + content hash)
4. **For each entry:**
   - Classify it (type, domain, certainty, impact, tags)
   - Check if it's already synced (via content_hash in state file)
   - If already synced → skip
   - If new/changed → create page in Notion with:
     - Properties in database (Name, Type, Domain, Certainty, Source, Confidence, Impact, Tags, Source File, Body preview)
     - Content blocks (the full formatted markdown)
   - Save the new page ID to state file
5. **Summary** → Print counts: created, updated, failed
6. **Log** → Write to sync-log.md for audit trail

---

### Why It's Smart

- **Idempotent**: Running it multiple times won't create duplicates (uses content hashing)
- **Intelligent classification**: Auto-tags everything, so you can filter/search in Notion
- **State tracking**: Remembers what it already synced in a JSON file
- **Orphan cleanup**: Optional `--cleanup` flag removes old pages that no longer exist locally
- **Dry-run mode**: See what would happen without making changes
- **Error resilient**: Continues even if one entry fails; logs failures separately- **Markdown preservation**: Converts your formatting to Notion blocks, preserving structure

---

You write this in `MEMORY.md`:


- **Body**: The full description as formatted Notion blocks
- **Source File**: "MEMORY.md"
- **Confidence Score**: 8 or 9 (because it's from MEMORY.md and has good length)

The `EntryClassifier` is the **brain** that automatically categorizes and tags your memory entries. It takes a raw entry (title + body) and assigns metadata like "this is a Research entry about AI Models with High impact."

### The Problem It Solves

When you write memory entries in plain English, Notion needs structured metadata to make them searchable and filterable. Manually tagging every entry would be tedious. The classifier automates this using **keyword pattern matching**.

---

### How It Works: The 5 Classifications

Each classification uses a dictionary of **keyword patterns** → **label**. It searches the title + body for those keywords.

### The `classify` Method: Putting It All Together

```python
def classify(self, entry: Dict) -> Dict:
    title = entry.get('title', '')
    body = entry.get('body', '')
    
    meta = {
        'content_type': self.classify_type(title, body),
        'domain': self.classify_domain(title, body),
        'certainty': self.classify_certainty(body),
        'impact': self.classify_impact(title, body),
        'confidence_score': self._estimate_confidence(title, body, entry.get('source')),
        'tags': self.extract_tags(title, body, entry.get('section', '')),
        'source': entry.get('source', 'Manual'),
    }
    entry['metadata'] = meta
    return entry
```

**Flow:**
1. Extract title, body, section from entry
2. Call each classification method
3. Pack results into `metadata` dict
4. Attach to original entry
5. Return enriched entry

---

### Design Characteristics

- **Keyword-based** (not ML): Fast, deterministic, no training needed
- **First-match wins**: Order of keywords matters (e.g., if a word appears in multiple domains, the first dictionary entry wins)
- **Lowercase matching**: Case-insensitive
- **Defaults**: Insight / General / Verified / Medium → safe defaults
- **Transparent**: Easy to debug (just check which keywords matched)
- **Extensible**: Add more keywords to dictionaries to improve accuracy

---

### Limitations (By Design)

- **No context awareness**: Can't understand sarcasm, nuance, or complex sentences
- **Keyword gaps**: If your writing style doesn't use the expected words, classification fails (e.g., you say "I discovered" instead of "realized" → may miss "Insight")
- **No ranking**: It's binary match/no-match; doesn't weigh keywords by strength
- **No learning**: Doesn't improve over time; you must manually tweak dictionaries

---

### In Practice

For your actual entries, it works surprisingly well because:
- Your memory files use consistent terminology (e.g., "Protocol", "Framework", "Strategy" → maps to content types)
- Domains are clear (AI models, OpenClaw, Trading) with distinctive keywords
- You tend to write with certainty (default "Verified" is often correct)
- Impact words are present when something is truly important

That's the EntryClassifier! Simple rule-based AI that turns free text into structured metadata.
