## Root Cause Analysis & Additional Fixes (Heartbeat at 11 PM UTC / 7 AM SGT)

### Broader Problem
The default session model changed from `stepfun/step-3.5-flash:free` to `qwen/qwen3.6-plus:free` at some point. Any cron job without an explicit `--model` override picked up the new default and started hitting Alibaba/OpenRouter rate limits ("Request rate increased too quickly"). This cascaded across dozens of jobs.

- Running every hour = 988+ accumulated runs, hammering the rate limit
- The cron was consuming OpenRouter token quota excessively
- Daily summary (10 AM SGT) still gathers insights; hourly is redundant and wasteful
- Can re-enable later at lower frequency (e.g., 4x/day) if needed
