### Build Environment Issues Encountered
1. **Rolldown native binding** — Vite 8 uses rolldown which requires native `@rolldown/binding-linux-x64-gnu`. Fixed by pinning `vite@6` (uses esbuild, no native deps). Pinned `@vitejs/plugin-react@5` for vite 6 compatibility.
2. **@types/react-dom** — react-dom@19.2.4 no longer ships declaration files and `@types/react-dom` keeps getting silently dropped by npm peer-dep resolution. Fixed by creating `src/react-dom-client.d.ts` type declaration.
3. **npm silent peer dep drops** — Multiple dev dependencies (`fake-indexeddb`, `@types/react-dom`, `@playwright/test`, `playwright`) silently fail to install even when specified in `--save-dev`. This is a consistent pattern in this environment's npm (likely Node 24 related). **Lesson**: For Node-side testing tooling, use globally available tools or write code that doesn't require local package installation.
4. **IndexedDB in Node** — Dexie requires IndexedDB. `fake-indexeddb` polyfill keeps failing resolution. **Workaround**: Use real browser testing (Playwright) or inline browser test pages.

### Key Design Decisions to Remember
- Per-set targets stored separately (not per-exercise aggregates) — each set can have different reps/weight
- `isPR` boolean on SetLog for fast "Recent PRs" queries on dashboard
- Compound index `[workoutExerciseId+setNumber]` for fast set target lookups during workout execution
- Media stored as raw Blob in IndexedDB (not base64) — Dexie handles natively
- Media `localFilePath` field renamed to `mediaBlob` (stores Blob directly)
