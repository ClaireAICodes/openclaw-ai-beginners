### [GREEN] MFA Code Orchestrator for Seamless Automation
**Category:** OpenClaw Workflow and Automation
**Risk Level:** green
**Confidence:** High

**Description:**
A secure, time-limited vault that stores MFA codes for cron jobs requiring human-in-the-loop authentication (e.g., MS Forms submission). The system can either automatically inject the code at runtime (if stored with short TTL) or send a timed Telegram prompt to Master with a one-click approval, ensuring submissions complete without manual intervention during busy hours.

**Rationale:**
The MS Forms submit cron fails if Master does not provide the MFA code precisely at 6 PM SGT. This creates a recurring friction point and risk of missed submissions. An orchestrator that manages codes securely and delivers them exactly when needed—either auto-injected or via smart reminder—eliminates this pain point and ensures compliance with daily reporting.

**Implementation Tasks:**
- Design secure storage for MFA codes (encrypted JSON with per-code TTL, stored in workspace/.secrets/)
- Build a retrieval API that cron jobs can call to get a valid code (with audit logging)
- For codes that cannot be stored securely (due to policy), implement a Telegram reminder system that sends a prompt at 5:55 PM with a "Provide Code" button; Master's response is captured and passed to the submit cron
- Add fallback: if no code provided within 5 minutes, retry with alternative method or flag for manual submission
- Integrate with the existing MS Forms submit cron to use this orchestrator instead of interactive prompt
- Test end-to-end: code retrieval → submission success

### [GREEN] Cron Auto-Repair Engine with Smart Backoffs
**Category:** OpenClaw Workflow and Automation
**Risk Level:** green
**Confidence:** High

**Description:**
An intelligent repair layer that integrates with the Cron Health Guardian to not only detect failures but also apply context-specific fixes: rate-limit errors trigger automatic model fallback (stepfun → minimax) with exponential backoff; missing configuration errors apply safe defaults; transient network errors retry up to 3 times; unrecoverable errors escalate to Master via Telegram with suggested remediation steps.

**Rationale:**
Many cron failures can be resolved without human intervention (e.g., model rate limits, temporary outages). Currently, these require manual patching. An auto-repair engine would dramatically reduce operational overhead and improve system reliability, directly addressing the pain point of "things breaking and needing my attention."

**Implementation Tasks:**
- Extend the health guardian to include a rules engine mapping error patterns to repair actions
- Implement fallback model list (stepfun → minimax → openrouter/anthropic) with circuit breaker to avoid hammering failing endpoints
- Add retry logic with jittered backoff for transient errors
- Create a repair log that records what was fixed automatically and what requires manual review
- Integrate with Telegram alerts: send concise summary of auto-repairs daily, and immediate alert for unrecoverable failures
- Test by simulating failures (rate limit, missing model, network drop) and verify auto-recovery
