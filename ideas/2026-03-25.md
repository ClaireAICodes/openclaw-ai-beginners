### [GREEN] Playwright Dependency Preflight & Self-Healing Wrapper
**Category:** OpenClaw Workflow and Automation
**Risk Level:** green
**Confidence:** High

**Description:**
A reusable Node.js module that Playwright-based skills invoke before launching the browser. It checks for required system libraries (libnspr4, libatk1.0-0, libatk-bridge2.0-0, libx11-xcb1, etc.), attempts automatic apt-get installation if missing, and verifies installation before proceeding. Wraps any Playwright script to ensure dependencies are met.

**Rationale:**
Today's MS Forms submission failure due to missing libnspr4 is symptomatic of a broader risk: any Playwright skill can break when system libraries are absent, especially on fresh deployments or after system updates. A preflight check prevents wasted cron runs, reduces debugging time, and enables self-healing for all automation relying on browser interaction.

**Implementation Tasks:**
- Catalog required system libraries for Playwright Chromium on Debian/Ubuntu (from official Playwright docs)
- Build a lightweight Node script that checks library presence via `ldconfig -p` and `which` for playwright itself
- Implement auto-install via `sudo apt-get update && sudo apt-get install -y <missing-packages>` with special handling for passwordless sudo in OpenClaw context
- Add retry logic: after installation, re-check before failing
- Create a wrapper function that skills can `require('./preflight')` and call `ensureDependencies()` before launching browser
- Update ms-forms-auto scripts to use the wrapper
- Test by uninstalling libnspr4 and verifying auto-recovery

### [GREEN] Consolidated OpenClaw Health Command
**Category:** OpenClaw Workflow and Automation
**Risk Level:** green
**Confidence:** High

**Description:**
A single CLI command (`openclaw health`) that aggregates the health status of the entire OpenClaw ecosystem: cron job execution history (recent runs, exit codes), installed skills (versions, outdated), system dependencies (missing packages), backup system (last success), and external integrations (auth validity, API connectivity). Outputs a concise health score (0-100) and a list of urgent alerts with fix commands.

**Rationale:**
Currently, system health is scattered across logs, memory files, and manual checks. Master lacks a quick health overview, leading to delayed detection of issues (like today's backup and MS Forms failures). A consolidated health command provides at-a-glance status, reduces cognitive load, and speeds up troubleshooting by surfacing actionable alerts in one place.

**Implementation Tasks:**
- Define health metrics: cron success rate (last 5 runs), skill uptime (last execution), dependency completeness (installed vs required), backup integrity (last run, warnings), auth validity (expiry dates)
- Build a Node.js script that queries each component: read cron logs, check daily-entries, run dependency checks, invoke backup dry-run, verify storageState files
- Create a scoring algorithm: assign weights and compute overall health percentage
- Generate actionable alerts: e.g., "Missing: libnspr4 → Run: sudo apt-get install -y libnspr4"
- Integrate as an OpenClaw plugin (`openclaw health`) or standalone script in bin/
- Add optional Telegram summary output for proactive monitoring
- Test on current system to verify accurate health state and useful recommendations
