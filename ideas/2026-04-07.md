### [GREEN] Cron Health Guardian & Auto-Recovery System
**Category:** OpenClaw Workflow and Automation
**Risk Level:** green
**Confidence:** High

**Description:**
A resilient monitoring system that continuously tracks cron job health, automatically detects failures (rate limits, model issues, auth problems), implements smart recovery (exponential backoff, alternative models), and maintains a health dashboard with proactive alerts. This prevents silent failures and reduces manual monitoring burden.

**Rationale:**
Recent April 6 incident revealed critical gaps: (1) cron jobs silently failed due to OpenRouter rate limits when default model changed, (2) no alert reached Master until manual discovery, (3) manual recovery was required for pre-fill, and (4) April 6 submission remains unsubmitted. Master's pain point is lack of time and mental load from routine tasks—this system automates exception handling so he never has to wonder "did my crons run?" and ensures submissions complete even when issues arise.

**Implementation Tasks:**
- Design health metadata schema (last_run, status, error_type, retry_count, model_used)
- Implement watchdog agent that polls cron history hourly via `openclaw cron list` and detects failures
- Create recovery rules engine: rate limit → backoff + model switch to alternative (e.g., minimax), auth errors → flag for manual refresh
- Build health dashboard (simple JSON output + daily summary notification)
- Add alerts for critical failures (submit crons, payment-related jobs) via Telegram
- Deploy as persistent cron itself (every 15 min) and integrate with existing daily plan
- Test with simulated failures and verify auto-recovery works
