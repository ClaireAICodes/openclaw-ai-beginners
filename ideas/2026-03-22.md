### [GREEN] Smart MFA Credential Recovery & Auto-Reset System
**Category:** OpenClaw Workflow and Automation
**Risk Level:** green
**Confidence:** High

**Description:**

A meta-automation system that monitors OpenClaw skills and automated scripts for authentication failures (invalid credentials, MFA expiration), then triggers a secure, pre-approved recovery workflow. It detects failures via exit codes or log patterns, requests one-time Master approval via Telegram interactive button, and uses stored recovery channels (backup email, phone SMS, authenticator app) to reset credentials and update config files automatically. After recovery, it retests the skill and reports success or escalation.

**Rationale:**
The ms-forms-auto skill is currently blocked because credentials appear invalid/expired. Manual credential reset interrupts automation and requires Master's time. A self-healing auth system ensures continuous operation of critical automations with minimal human involvement. It's a force multiplier: once configured, it maintains the automations that maintain Master's life. The green risk is maintained because recovery channels are pre-approved and any external contact (email/SMS) only happens after explicit per-incident approval.

**Implementation Tasks:**
- Define failure detection: monitor exit codes (1=cred error, 2=MFA needed, etc.), parse log files for keywords ("Invalid credentials", "account locked")
- Create a registry of auth-dependent skills/scripts with their config paths (credentials.json, storageState.json, etc.) and recovery methods (email reset, SMS code, authenticator app backup)
- Build Telegram approval flow: send message with "Approve Recovery" button; include skill name, error details, and estimated recovery steps
- Implement recovery adapters:
  * Email-based reset: use IMAP to monitor inbox for reset links, auto-click using Playwright (with caution)
  * SMS-based: if Twilio or phone API available, auto-read SMS codes
  * Authenticator app: use stored backup codes or otpauth URL to generate TOTP
- After approval, securely update config files (preserve JSON structure), clear old sessions, and re-run the skill once to verify
- Notify Master of outcome; if recovery fails after X attempts, escalate to manual
- Store recovery audit log: who approved, when, outcome
- Package as an OpenClaw daemon or cron job (run every 15 minutes checking recent failures)
- Add configuration: Master can whitelist which skills are auto-recoverable, set max retry counts, choose recovery channel precedence

### [GREEN] Voice-Driven Gym Workout Logger with Wearable Integration
**Category:** Hobbies & Interests / Lifestyle & Habits
**Risk Level:** green
**Confidence:** High

**Description:**

A frictionless workout logging PWA that uses voice commands to record exercises, sets, reps, and weight, and automatically enriches entries with wearable sensor data (heart rate, calories, workout duration) from smartwatches. Offline-first with cloud backup; includes progressive overload suggestions and weekly progress reports. Voice entry allows hands-free logging immediately after sets, ensuring no data is forgotten. Wearable integration adds objective intensity metrics without manual entry.

**Rationale:**
Master goes to the gym weekly but likely doesn't track workouts consistently due to effort required. The previous gym app concept was a manual form. Voice commands plus wearable sync make logging truly effortless: just speak "bench press three sets of ten at 60kg" and the app captures it, then pulls HR/calories from the watch. This increases adherence dramatically, leading to better fitness outcomes. It's a green project: local storage, optional cloud sync, no external APIs for core functionality. The scope is reasonable (2-3 days for MVP voice+watch prototype).

**Implementation Tasks:**
- Design voice grammar: wake word optional, command patterns like "[exercise] [number] sets of [number] at [weight] kg" with optional notes
- Implement voice capture using Web Speech API (browser) or native Speech Recognition on mobile (PWA with permissions)
- Parse spoken commands into structured data (exercise name, sets, reps, weight, RPE if mentioned)
- Create exercise dictionary with common lifts and muscle groups; allow custom additions
- Integrate with wearable APIs:
  * Apple Watch: use HealthKit data via companion app or export to Health app and read via Web Bluetooth? (may need native app)
  * Wear OS: Google Fit API access
  * Generic: Bluetooth LE heart rate service for real-time HR during workout
- Store sessions in IndexedDB with timestamp, exercises, voice notes (optional), sensor data (average HR, peak HR, calories)
- Generate weekly report (markdown): total volume, PRs detected, intensity metrics (time under tension, HR zones), suggestions for next week (increase weight if all reps completed easily)
- Add progressive overload nudges: when an exercise shows consistent >8 reps across sets, suggest adding weight
- Build as PWA with offline capability; option to export/import JSON for backup
- Deploy to GitHub Pages or Vercel; share link with Master to add to home screen
- Test with sample voice inputs and simulated wearable data; iterate on recognition accuracy
